Phase detail

  • PR #6
    Phase 0 — Baseline. Corrected spec scope and recorded the guided 10-phase plan in AGENTS.md; verified the environment before any build work started.
  • PR #7
    Phase 1 — Data layer. PostgreSQL schema via pg-axi: a single tasks table (sql/schema.sql) with status as a check constraint, not a separate boards/columns entity.
    Review-loop catch: dev Postgres port bound to localhost only.
  • PR #8
    Phase 2 — Web Awesome frontend scaffold. Static/mock three-column board (frontend/index.html, app.js, styles.css), Web Awesome via CDN only, no backend wiring yet.
    Review-loop catch: inaccurate wa-card slot comment fixed.
  • PR #9
    Phase 3 — Wire frontend to data. Thin backend/server.js (plain node:http + pg, no framework) serving both the static frontend and a JSON /api/tasks API on one origin.
    Review-loop catch: added try/catch + pool error handler to prevent backend crashes.
  • PR #10
    Phase 4 — Source-control & review workflow. Documented the gh-axi branch/PR conventions already in organic use since phase 0 — fm/<task-id> branches, PR template with Intent/Verification, manual review as the real (only) merge gate.
  • PR #11
    Phase 5 — Browser testing. tests/browser/golden-path.sh drives the live app through chrome-devtools-axi (create/move/edit/delete + 2 edge cases), asserting every mutation against /api/tasks, not just DOM state.
  • PR #12
    Phase 6 — Containerization. backend/Dockerfile added to docker-compose.yml; whole app now starts with docker compose up -d, same host port 3001.
    Review-loop catch: browser-test README pointed at the containerized single-command startup.
  • PR #13
    Phase 7 — Kubernetes deployment. Plain YAML manifests under k8s/ (no Kustomize/Helm) deploy backend + Postgres to a local kind cluster via kubernetes-axi, mirroring the compose topology.
    Review-loop catches: livenessProbe switched to TCP socket check; stale kubernetes-axi phase-status note fixed in spec doc.
  • PR #14
    Phase 8 — Quota-aware dispatch practice. No app code — docs/quota-dispatch.md documents how quota-axi reports per-provider quota windows so a supervisor can route to whichever harness has real headroom.
  • this phase
    Phase 9 — Human review practice (current). No app code — this artifact itself is the practice: a real lavish-axi review surface built from this repo's own history, opened and confirmed rendering. See docs/human-review-practice.md.
